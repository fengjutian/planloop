# 记忆值不值：第二次同类任务快多少（真实模型，`fee` 族）

> 这份文档回答 [market-scan.md](market-scan.md) §四 第 5 条那个一直没做的度量：
> **记忆到底值不值那些代码**。装置：同一个仓库、同一个任务族的两道任务——
> 第一道任务修折扣逻辑（并因此踩坑），第二道任务改同一个文件（回归风险最高的那种）。
> 对照臂**完全无记忆**，其余臂分别只开一个记忆子系统，判分统一用**仓外判据**。
>
> 模型是**真实模型**（MiniMax-M3.1-Flash，temperature 0.2，同一模型、同一任务，只有记忆不同）。
> 模式：**real**，任务族：**fee**，重复 **8** 次。
> 数据：`.membench-fee16`（8 reps，**三臂全部有效**，canary 扫描**零污染**）。
>
> **这一族是为了修掉上一族的装置缺陷才做的**：
> `contract` 族的契约**猜得出来**，那次核对是自愿的，记忆没有东西可省
> （[上一族报告](memory-value.md) §六 / [bench.md](bench.md) §二十一）。
> 这里平台费**按折扣档位**取值，`pct(10) == 0.88` **推不出** `pct(20) == 0.75`，
> 于是"查表"从**可选确认**变成**必需动作**。
>
> ⚠️ **上一版（`.membench-fee9`）的数字已撤回**，理由有两条：
> ①模型用 shell 读到了仓外判据的**源码**（`run` 走 shell，而工作区锁只管 `read`/`write`），
> **答案就在源码里**；失败反馈的 traceback 还会把答案打印出来
> （[bench.md](bench.md) §十九.12）；
> ②**这套装置的效应量比它看起来小**——本文件量出来的**噪声地板是 ±48% 步数 / ±52% tokens**，
> 而 fee9 当时宣称的"-45% tokens"其实只是勉强在地板之上（见 §一.2 与 §四.3）。
>
> 复现：
> ```bash
> python -m planloop membench --real --family fee --model MiniMax-M3.1-Flash --reps 8 \
>   --dir .membench-fee16 --out .demo/membench-fee16.md
> python -m planloop membench --analyze --family fee --dir .membench-fee16   # 回读行为
> python -m planloop membench --verify --family fee --dir .membench-fee16 \
>   --report .demo/membench-fee16.md                                          # 重算 + 交叉核对
> ```
> **本文件的每个数字都是 `membench --verify` 从原始产物重算出来的**，
> 不是手打的（手打过一次，同一份文档里错了 4 处）。
> 交叉核对的结果：**报告与事件流无不一致**（只有一条 NOTE：旧报告的去重口径不可复算，见 §二表下）。

## 一、结论

**先说最重要的一条：这个装置有噪声地板，而且地板比效应大。**

### 1.1 噪声地板（A/A 对照，藏在设计里）

在**教训臂没有教训可注入**的那 3 次重复里（rep 1/2/3），
教训臂的 prompt **和对照臂逐字相同**（记忆块是空的）。
两臂的差**就是模型自己的方差**：

| 同 prompt 的两臂 | 到验收通过：步数 | 到验收通过：tokens | 查档位表次数 |
|---|---|---|---|
| 对照臂 | 2.7 | 2813 | 14 |
| 教训臂（无记忆） | 4.0 | 4286 | 17 |
| **差** | **+48%** | **+52%** | **+21%** |

⇒ **任何小于这个量级的"收益"都分不清是记忆的功劳还是模型今天心情好。**
（这条地板是免费的：A/A 对照就藏在"注入率"这个设计里。）

### 1.2 唯一站得住的效应：**行为**（查表次数）

| 口径 | 对照 → 事实臂 | 相对噪声地板（±21%） |
|---|---|---|
| **查档位表次数** | **72 → 36（-50%）** | ✅ **在噪声之上**，8 次里 7 次更少 |
| 到验收通过的步数 | 3.0 → 2.2（-27%） | ❌ 落在地板（±48%）内 |
| 到验收通过的 tokens | 3525 → 2783（-21%） | ❌ 落在地板（±52%）内 |
| 总 tokens | 16657 → 14711（-12%） | ❌ 落在地板内 |

⇒ **一句话**：**已验证事实确实替掉了一次"必需"的查表**——
这是记忆在这个装置上唯一测得出来的收益；
而"少走多少步、少花多少 token"**在这个样本量下测不出来**（效应量比噪声小）。

### 1.3 教训臂（`memory.py`）：这轮**没测出**可测收益

- 教训**确实产出了**：8 次重复里 **5 次**（rep 4~8）留下了模型自己写的教训
  （`source: model`，触发条件是具体文件列表，第九处失效已修），
  它们进了 **92/133** 个 prompt。
- 但它**没有替掉任何核对**：查档位表 **72 → 92 次（反而更多）**，
  成本上也没省（tokens -4%，在噪声内）。
- ⇒ **不能说教训有用，也不能说它没用**：它在这轮既没省事，也没帮上忙，
  而"两臂差多少"这个量级根本分辨不出来（噪声 ±48%）。
- 正确性口径：教训臂 6/8 绿、事实臂 8/8 绿、对照 6/8 绿——**差 2 次重复，不能下结论**。

### 1.4 五次"红"是同一类，而且**事实臂一次都没红**

- 对照臂 **3 次红**（rep 4/5/6）、教训臂 **2 次红**（rep 4/6）、事实臂 **0 次红**。
- 红的形态全是同一类：`blocked`（步数用尽）、
  **仓库自己的测试是绿的**、**仓外最终判据判红**——
  模型把"`member_pct=0`（没有会员折扣）"这个情况写坏了，
  而节点的验收**不看**这个情况。
  这正是"节点过了、仓库还是红的"那条缝（[bench.md](bench.md) §二十一.3）。
- ⇒ 方向一致（事实臂 8/8 全绿），但 **n=8 差 2 次不构成结论**，
  按 §1.1 的纪律只能记为"方向一致、证据不足"。

> **一句话结论**：在这个任务族上，
> **记忆的可测收益只有一条——已验证事实让模型少查一半的档位表**；
> **成本口径测不出来**（地板比效应大）；
> **模型写的教训这轮没有任何可测收益**（进了 prompt，也没省事）。
> ⇒ 两条记忆路径**不是"收益重合"，是分工不同**：事实=知识（省一次查表），
> 教训=保险（本轮连保险费都没算出来）。

| 臂 | n | 外部判定为绿 | 仓库全量测试为绿 | 到验收通过：步数 | 到验收通过：tokens | 总 tokens | 平均 L1 失败 | 护栏拦截 | 带教训的 prompt | 带事实的 prompt | 查档位表 | 无效回复 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| R2 无记忆（对照） | 8 | **6/8** | 6/8 | 3.0 | 3525 | 16657 | 1.2 | 0 | 0/120 | 0/120 | **72 次** | 3 |
| R2 教训+护栏 | 8 | **6/8** | 6/8 | 2.8 | 3378 | 21531 | 1.2 | 0 | **92/133** | 0/133 | 92 次 | 0 |

> **「到验收通过」那两列才是工作量**：执行器要等模型「自己宣布完成」才停，
> 真实模型做完之后还会反复跑同一套测试——那是模型的确认习惯，不是工作量。
> 总步数 / 总 tokens 因此会被顶满，不该当成本口径。
>
> **「L1 失败」这一列有一处口径差异**（门报了一条 NOTE）：
> 这一轮的报告是修口径之前生成的，它数的是**去重后的失败**，
> 而事件流逐次记录失败；32 行里有 1 行（`R2_memory` rep 5）对不上。
> 聚合值不受影响（1.2 / 1.2 / 1.0，逐次口径重算后完全相同），
> 所以这一列**不作为任何结论的依据**；新装置已改成与日志同口径。

## 四、行为归因：从事件流回读"模型到底做了什么"

| rep | 对照臂 查表/第一步 | 教训臂 查表/第一步 | 事实臂 查表/第一步 |
|---|---|---|---|
| 1 | 6 / read shop/helpers.py | 8 / read shop/helpers.py | **4** / read shop/helpers.py |
| 2 | 5 / read shop/helpers.py | 5 / read shop/helpers.py | 6 / read shop/helpers.py |
| 3 | **3** / run `sed -n '1,200p' shop/helpers.py` | 4 / read shop/helpers.py | 4 / read shop/helpers.py |
| 4 | 8 / read shop/helpers.py | 21 / read shop/helpers.py | **5** / read shop/helpers.py |
| 5 | 19 / run `sed -n '1,200p' shop/helpers.py` | 17 / read shop/helpers.py | **5** / run `pwd && printf …` |
| 6 | 21 / read shop/helpers.py | 21 / read shop/helpers.py | **6** / read shop/helpers.py |
| 7 | 6 / read shop/helpers.py | 9 / read shop/helpers.py | **3** / read shop/helpers.py |
| 8 | **4** / run `pwd && printf …` | 7 / read shop/helpers.py | **3** / read shop/helpers.py |
| **合计** | **72** | **92** | **36** |
| **比对照臂更少** | — | 4/8 | **7/8** |

三条读法：

1. **事实臂确实少查**（72 → 36，-50%，8 次里 7 次更少）。
   它带的那条**已验证事实**写的就是档位表和公式，
   所以它**不必打开 `shop/helpers.py` 就能算对**——
   这就是"记忆替掉了一次**必需**的查表"，是本项目在真实模型上
   **唯一测得出来**的记忆收益。
2. **教训臂没替掉任何核对**（72 → 92，反而更多）。
   模型写的教训是**契约转述**（"漏掉了档位平台费，总价 270 而不是 264"），
   不是档位表本身——**转述不能代替查表**，所以模型照样去打开文件核对。
   ⇒ 这条结论和上一轮一致，而且这次有理由了：
   **教训的保真度不够，它携带的是"结论"而不是"知识"**。
3. **对照臂的 3 次红和它查表次数最多是同一件事**：
   rep 5/6 的对照臂查了 19/21 次文件，24 步用尽、`blocked`，
   最后仓库里的 `member_pct=0` 那个情况是坏的 ⇒ 仓外判据判红。
   ⇒ **查表不是"可选确认"，是"必需动作"；查不完就会卡住**——
   这正是这一族当初被设计成"契约不可猜"的原因。

### 4.3 和被撤回那一版的对照（为什么撤回）

| | fee9（已撤回） | fee16（本文件） |
|---|---|---|
| 判据是否被模型读到 | **是**（3 次用 shell 读到源码；traceback 还带答案） | **零**（判据从 stdin 喂，canary 扫描 8/8 clean） |
| 宣称的成本收益 | 步数 -47%、tokens **-45%** | 步数 -27%、tokens -21% |
| 同 prompt 的噪声地板 | 步数 ±33%、tokens ±29%、查表 ±19% | 步数 **±48%**、tokens **±52%**、查表 ±21% |
| 结论 | 撤回（污染 + 效应量没对照地板） | **只有行为口径站得住** |

⇒ 上一版之所以敢写"-45% tokens"，是因为**没人量过同 prompt 的两臂能差多少**。
⇒ **报告效应之前，先报 A/A 地板**——这条纪律是这轮最贵的教训换来的
（[roadmap.md](roadmap.md) 的「噪声地板门」）。

## 五、装置说明（为什么任务族长这样）

1. **契约不再是显然公式**：平台费**按折扣档位**取值（0%→0.00、10%→0.02、20%→0.05），
   所以 `pct(10) == 0.88` **推不出** `pct(20) == 0.75`。
   可见测试只钉 10% 那一行；20% 那一行**只有读文件才知道**。
2. 第二道任务的 prompt **不带** `shop/helpers.py`（"查表"是**必需动作**）；
   第一道任务带它——**拿掉它试过，装置被改坏并已回退**（[bench.md](bench.md) §十九.13）。
3. **判据必须真的读不到**（这一条是这轮补上的，之前一直只是"在仓外"）：
   - 判据**从 stdin 喂给 python**（`python -`），**磁盘上根本没有它**——
     不是"在仓外"，是"任何时刻都不存在文件"；
   - 从 stdin 来的程序，traceback 里**没有源码行**——
     而失败那一行正是写着答案的那行（上一版实测：反馈里出现了 `198.0`）；
   - 判据的**要求**用一句**不含数字**的话告诉模型（"total() 必须接受第三个参数
     member_pct，并且用同一个换算函数"），
     这样失败反馈说得出**该改什么**——只给一个 `exit=1` 或裸 `TypeError`，
     模型会原地打转（实测：同一个文件连读 16 次）。
   - 答案键（判据源码）**不序列化**：持久化的计划里只有判据 id。
4. **判据要自己证明自己没被读到**：每次重复的判据带一个唯一 canary，
   跑完扫事件流和工作区——**命中即判该次重复被污染**，从样本里剔除并明确报出来。
   ⇒ "判据被藏住了"从此是**可查的**，不是一句声明。
   ⚠️ **这条自证本身也有过洞**（[bench.md](bench.md) §十九.14）：
   扫描按报告里的臂名拼文件名，而第一道任务的日志叫 `events_setup_N`，
   于是**第一道任务从来没被扫过**——而模型读判据源码恰恰发生在那儿。
   现在臂名 → 日志名的映射单列一张表，并有守卫测试。
5. **噪声地板是装置的一部分**：装置必须能算出"同 prompt 的两臂差多少"
   （本文件的 §1.1），**否则报出来的效应量无从判断真假**。

守卫测试：
`tests/test_membench.py::FeeFamilyTest`（其中最关键的一条是**反证**）：

```python
def test_a_model_that_never_reads_the_file_fails(self):
    """把「显然公式」写进仓库，仓外判据必须判它不通过。"""
```

如果这条不成立，装置就退回到"测不出东西"的状态——上一族正是栽在这里。
判据本身的守卫在 `tests/test_heldout.py`（判据不落盘、失败输出不含答案、
判据仍能判红判绿、payload 不进 prompt 也不进持久化计划、canary 能查出泄漏**且能扫到第一道任务**）。
发布前的门在 `planloop/membench_verify.py`（重算 + 交叉核对 + 污染剔除 + 噪声地板），
守卫在 `tests/test_membench.py::VerifyTest`。

## 六、这份数字不证明什么

1. **成本口径不成立**：噪声地板（±48% 步数 / ±52% tokens）比观测到的效应
   （-27% / -21%）还大 ⇒ **"记忆更省"这句话，这轮的数据证明不了**。
2. **正确性差异只有 2 次重复**：事实臂 8/8 绿 vs 对照 6/8 绿，
   方向明确（3 次红全在对照臂、全是"查表查不完、步数用尽"），
   但 **n=8 差 2 次不能下结论**。
3. **教训臂这轮没测出收益**（本轮最重要的一条）：
   教训在 5/8 次重复里真进了 prompt（92/133 个 prompt），
   但它**没替掉任何核对**（查表 72 → 92）、**成本也没省**（-4%，噪声内）。
   ⇒ 既不能说有用，也不能说没用。
   ⇒ 而且**产出率本身装置控制不了**：契约在 prompt 里时它有时一次做对（3/8 次没有教训），
   契约不在 prompt 里时它**卡住**（连读 24 次、任务 `blocked`、没有教训）——
   两条路都通向"没有教训"（[bench.md](bench.md) §十九.13）。
4. **一个任务族、一个模型**：别的族（性能、并发、依赖升级）和别的模型没测。
5. **没有对照组「模型更强」**：真正该比的不是「有记忆 vs 没记忆」，而是「有记忆 vs 换个更强的模型」。
6. **只有 8 次重复**：要把 -20% 左右的成本效应从 ±50% 的噪声里分辨出来，
   需要的样本量是**数量级**级别的（每臂几十次），本轮做不到。

## 七、决策含义

- **记忆这条路第一次测到了"行为收益"，但没测到"成本收益"**：
  已验证事实让模型**少查一半的档位表**（72 → 36，8 次里 7 次更少），
  这是真效应（在 ±21% 的查表噪声之上）。
  而"少走几步、少花几个 token"**在这个样本量下不可测**。
  ⇒ **上一轮（fee9）"记忆省 45% tokens"的说法，到此正式作废**——
  它既被污染过，也从来没有对照过噪声地板。
- **两条路径不是"收益重合"，是分工不同，而且这轮只证实了一半**：
  `memdb.py` 的**已验证事实 = 知识**（省掉一次必需查表 ✅ 已测到）；
  `memory.py` 的**教训 + 护栏 = 保险**（❌ 本轮没测到收益，
  因为模型写的教训是**契约转述**——带的是"结论"不是"知识"，替代不了查表；
  护栏 8 次里拦截 0 次）。
  ⇒ **教训的保真度问题（转述 ≠ 知识）现在有了直接证据**，
  这比"教训没收益"这个结论本身更值得记。
- **优先级 6（记忆价值重测）没有结束，但问题变清楚了**：现在要回答的不再是
  "记忆有没有用"，而是三个更具体的问题，且**顺序不能反**：
  ①**先降噪**：要么把重复次数提上去（每臂几十次），要么换一个效应量更大的任务族，
     否则任何小于 ±50% 的结论都测不出来；
  ②**再改教训的保真度**：让教训携带**可复用的知识**（表、公式）而不是转述，
     否则它永远替代不了查表；
  ③**最后才谈合并/取舍**（"事实臂要不要也配一条护栏"）。
  ⇒ 在①完成之前，**不合并、不加功能**。
