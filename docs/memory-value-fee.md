# 记忆值不值：第二次同类任务快多少（真实模型，`fee` 族）

> 这份文档回答 [market-scan.md](market-scan.md) §四 第 5 条那个一直没做的度量：
> **记忆到底值不值那些代码**。装置：同一个仓库、同一个任务族的两道任务——
> 第一道任务修折扣逻辑（并因此踩坑），第二道任务改同一个文件（回归风险最高的那种）。
> 对照臂**完全无记忆**，其余臂分别只开一个记忆子系统，判分统一用**仓外判据**。
>
> 模型是**真实模型**（MiniMax-M3.1-Flash，temperature 0.2，同一模型、同一任务，只有记忆不同）。
> 模式：**real**，任务族：**fee**，重复 **8** 次（**有效 5 次**）。
>
> **这一族是为了修掉上一族的装置缺陷才做的**：
> `contract` 族的契约**猜得出来**，那次核对是自愿的，记忆没有东西可省
> （[上一族报告](memory-value.md) §六 / [bench.md](bench.md) §二十一）。
> 这里平台费**按折扣档位**取值，`pct(10) == 0.88` **推不出** `pct(20) == 0.75`，
> 仓外判据**不打印期望值**——于是"查表"从**可选确认**变成**必需动作**。
>
> 复现：
> ```bash
> python -m planloop membench --real --family fee --model MiniMax-M3.1-Flash --reps 8 \
>   --dir .membench-fee --out .demo/membench-fee.md
> python -m planloop membench --analyze --family fee --dir .membench-fee   # 回读行为
> ```

## 一、结论

- **样本说明**：8 次重复里，**rep 6/7/8 的模型调用直接失败**（0 tokens，模型根本没回答，
  仓库都没被碰过）——那是**装置坏了**，不是任务结果，**不计入**下面的绿/红统计。
  **有效样本 = 5 次重复 × 3 臂 = 15 次运行。**
- 第一次任务（R1）留下：教训 [1, 0, 1, 1, 1] 条、已验证事实 5 条
  （rep 2 的 R1 被**安全闸门**拦下：模型用了带 `;` 的子 shell 命令、需要人工批准、
  基准里没人批准 → 那一轮**没有教训可注入**，事实臂不受影响）。
- **其中 3/5 条教训是模型自己写的**；另 1 条**退化成了兜底模板**（模型只交了思考过程、没交答案）。
- 第二次任务，**无记忆**：外部判定为绿 **4/5**
- 第二次任务，**教训+护栏**：外部判定为绿 **5/5**，教训出现在 **48/65** 个 prompt 里
- 第二次任务，**只有已验证事实**：外部判定为绿 **3/5**，事实出现在 **60/60** 个 prompt 里
- **成本口径（对照 vs 事实，两臂验收集合相同）**：做到验收通过要 **3.0 → 1.6 步**，
  **3579 → 1975 tokens（-45%）**。
- **行为口径（对照 vs 事实，从事件流回读）**：隐藏约定被打开 **29 → 17 次（-41%）**，
  而且**5 次里有 4 次更少**（第 3 次持平）。
- **正确性口径（对照 vs 教训+护栏）**：**4/5 vs 5/5**；护栏拦截 0 次。
- **三次"红"全是同一类**：节点的验收**过了**，仓外最终判据**判红**——
  模型把"`member_pct=0`（没有会员折扣）"这个情况写坏了，而节点的验收**不看**这个情况。
  这正是"节点过了、仓库还是红的"那条缝（[bench.md](bench.md) §二十一.3）。

> **一句话**：**这是第一次在真实模型上测到记忆的成本收益**——
> 已验证事实让模型少查 41% 的表、少花 45% 的 tokens；
> 而**模型自己写的教训没有带来任何成本收益**（2.2 步 / 2817 tokens，夹在中间）。
> 正确性差异只有 1 次重复，**不能**下结论。

> **「到验收通过」那两列才是工作量**：执行器要等模型「自己宣布完成」才停，
> 真实模型做完之后还会反复跑同一套测试——那是模型的确认习惯，不是工作量。
> 总步数 / 总 tokens 因此会被顶满，不该当成本口径。

## 四、行为归因：从事件流回读"模型到底做了什么"

| rep | 对照臂 动作/看约定 | 教训臂 动作/看约定 | 事实臂 动作/看约定 | 事实臂的第一步 |
|---|---|---|---|---|
| 1 | 12 / 5 | 12 / 6 | 12 / 4 | read shop/helpers.py |
| 2 | 12 / 5 | 12 / 4 | 12 / 3 | **write shop/pricing.py** |
| 3 | 12 / 4 | 12 / 7 | 12 / 4 | read shop/helpers.py |
| 4 | 12 / 6 | 12 / 5 | 12 / 3 | read shop/helpers.py |
| 5 | 12 / 5 | 12 / 4 | 12 / 3 | **write shop/pricing.py** |
| **合计** | **29** | **26** | **17** | |

三条读法：

1. **事实臂确实少查**（29 → 17 次，-41%，5 次里有 4 次更少），
   而且**有 2 次它的第一个动作就是直接写代码**——它不需要先看文件就知道档位表。
   这就是"记忆替掉了一次**必需**的查表"，是本项目第一次在真实模型上测到记忆的**成本收益**。
2. **教训臂没有收益**（26 次，比对照臂的 29 还少一点，但步数 2.2 vs 3.0、tokens 2817 vs 3579，
   优势很小，而且它的**总 tokens 最高** 17679）——
   模型自己写的教训把契约**转述**了一遍，模型仍然要去核对。
3. **事实臂的 2 次红，和对照臂的 1 次红，是同一类**：节点的验收过了，仓外最终判据判红。
   事实臂"更快"的那部分，正好是它**没去核对**的那部分——
   而"没核对"就意味着模型没发现它把 `member_pct=0` 那个情况写坏了。
   **这是速度与正确性的直接交换**，不是免费的午餐。

## 五、装置说明（为什么任务族长这样）

这一族是为了修掉 `contract` 族的**装置缺陷**：

1. **契约不再是显然公式**：平台费**按折扣档位**取值（0%→0.00、10%→0.02、20%→0.05），
   所以 `pct(10) == 0.88` **推不出** `pct(20) == 0.75`。
   可见测试只钉 10% 那一行；20% 那一行**只有读文件才知道**。
2. **仓外判据不泄题**：断言消息是固定字符串，**不打印期望值**，
   但**带诊断**（"member_pct has to go through the same conversion helper"）——
   纯数字隐藏会让模型没有线索可查（实测：它把同一条检查跑了 5 遍、代码一行没改）。
3. 第二道任务的 prompt **不带** `shop/helpers.py`，"查表"是**必需动作**。

守卫测试在 `tests/test_membench.py::FeeFamilyTest`，其中最关键的一条是**反证**：

```python
def test_a_model_that_never_reads_the_file_fails(self):
    """把「显然公式」写进仓库，仓外判据必须判它不通过。"""
```

如果这条不成立，装置就退回到"测不出东西"的状态——上一族正是栽在这里。

## 六、这份数字不证明什么

1. **有效样本只有 5 次重复**：8 次里 3 次死于模型调用失败（0 tokens）。
   正确性差异只有 1 次重复，**不能**说记忆让模型更马虎，也**不能**说它更安全。
2. **一个任务族、一个模型**：别的族（性能、并发、依赖升级）和别的模型没测。
3. **成本差异里混着"少查表"和"少验证"**：事实臂便宜，一部分是因为它**没核对**，
   而它因此错过了两个回归。**便宜不等于更值**——这一族的净收益目前**算不上正**。
4. **教训臂的处理很弱**：5 次重复里只有 3 次拿到模型自己写的教训
   （1 次 R1 被安全闸门拦下、1 次教训退化成兜底模板）。
   所以"模型写的教训没收益"这句话，**证据强度不如**"已验证事实有收益"那一句。
5. **装置本身还有两个已知缺口**（本轮发现，未修）：
   ①安全闸门会悄悄抽掉一个臂的处理（R1 被拦 → 没有教训）；
   ②模型调用失败会被算成任务失败（本轮已改成单独标记，但这份数字是改之前跑的，手工剔除了）。
6. **没有对照组「模型更强」**：真正该比的不是「有记忆 vs 没记忆」，而是「有记忆 vs 换个更强的模型」。

## 七、决策含义

- **记忆这条路第一次测到了收益，而且收益来自"已验证事实"**：
  步数 -47%、tokens -45%、查表 -41%（5 次重复里 4 次更省）。
  这**推翻**了上一轮"记忆在真实模型上只是成本"的结论——
  上一轮之所以测不出，是因为**契约可猜**（装置缺陷），不是记忆没用。
- **模型写的教训（`memory.py`）仍然没有测到收益**，而且它有**保真度风险**：
  教训生成器曾经只拿到"wrote 239 chars"这样的摘要，于是**编了一个原因**
  （[bench.md](bench.md) §十九.7）。已修（把文件真容给它），但本轮的有效样本里
  真正拿到"模型自己写的"教训的重复只有 3 次，**这一条还没测透**。
- **两条路径不是"收益重合"，是分工不同**：
  `memdb.py` 的**已验证事实 = 知识**（省一次查表，但省掉的是核对）；
  `memory.py` 的**教训 + 护栏 = 保险**（本轮护栏拦截 0 次——因为这个族的回归
  在可见测试之外，只有仓外判据看得见）。
  ⇒ **合并/取舍不能只看收益，还要看保真度和它防的是什么**。
- **优先级 6（记忆价值重测）没有结束，但问题变了**：
  现在要回答的不再是"记忆有没有用"，而是
  **"记忆省下来的那次核对，值不值它带来的漏检"**——
  也就是**要不要给"事实"也配一条护栏**（让知识臂也带一道保险）。
  这是下一轮该测的。
