# 判据召回率：故障注入集

> 目的：测「验收层能不能抓住**已知**的失效」。这跟 [bench.md](bench.md) 问的问题不同——
> bench 问「有反馈能不能让模型改对」，这里问「判据本身够不够尖」。
> 判据若对什么都放行，bench 会给出 100% 的成功率，而且理由完全错误。
>
> 装置：对每个任务注入一批**已知**缺陷（mutant），分别用两个判据跑：
> - **强判据**：工作区外的 held-out oracle（模型读不到、改不到）；
> - **弱判据**：工作区里模型自己写的那份可见测试（模型能改）。
>
> 三道对照，防止判据「假装很尖」：正确实现必须通过；语义等价的改写（neutral）必须通过；
> 每个 mutant 还要和正确实现做**行为探针**对比——行为一样的 mutant 是**等价 mutant**
> （注入的其实不是缺陷），不计入召回率分母。

## 一、结论

- **强判据召回率 33/33 = 100%**
- 弱判据召回率 13/33 = 39%
- 过杀（正确实现 / 等价改写被拒）：强判据 0 次，弱判据 0 次
- 等价 mutant（注入无效，已剔除）：0 个
- **只被强判据抓住的缺陷：20 个**——这正是「模型自己写测试」换不来的部分
- 强判据真漏检：0 个

| 案例 | 缺陷数 | 强判据抓到 | 弱判据抓到 | 正确实现通过（强/弱） | 等价改写通过（强/弱） |
|---|---|---|---|---|---|
| `calc_divide` | 10 | 10/10 | 5/10 | ✅ / ✅ | ✅ / ✅ |
| `stats_mean` | 11 | 11/11 | 3/11 | ✅ / ✅ | ✅ / ✅ |

## 五、这份数字不证明什么

1. 召回率是**相对于我们自己定义的缺陷分类**。未知缺陷不在分类表里，
   所以高召回只说明「已知分类里没有盲区」，**不等于**真实任务上的召回率。
2. 强判据也不是无限的：它只能检查它写了的断言。判据写了什么、漏了什么，
   同样是天花板的一部分——本表测的是「注入的缺陷 vs 写下的断言」，不是「需求 vs 实现」。
3. 样本量小：每个案例 10~12 个缺陷、每缺陷 1 次运行，没有重复采样，也没有置信区间。
4. 本表**没有调用模型**：它测的是判据，不是 agent。模型侧的效果在 [bench-summary.md](bench-summary.md)。
5. **方法论备注**：第一轮跑出来有 1 条「漏检」，分诊后发现是**等价 mutant**——
   注入的缺陷本身语义没变（`if TAX_RATE < 0` 的分支永远不触发，但后面的正确计算还在）。
   判据没错，是注入无效。现在这三种状态由行为探针自动分诊，不再靠人眼。
