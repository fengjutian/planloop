# 记忆值不值：第二次同类任务快多少

> 这份文档回答 [market-scan.md](market-scan.md) §四 第 5 条那个一直没做的度量：
> **记忆到底值不值那些代码**。装置：同一个仓库、同一个任务族的两道任务——
> 第一道任务修折扣逻辑（并因此踩坑），第二道任务改同一个文件（回归风险最高的那种）。
> 对照臂**完全无记忆**，其余臂分别只开一个记忆子系统，判分统一用**仓外判据**。
>
> 模型是**脚本模型**（确定性，可复现），所以这份数字量的是**机制**，不是真实模型。
> 模式：**scripted**，任务族：**demo**，重复 **1** 次。

## 一、结论

- 第一次任务（R1）留下：教训 [1] 条、已验证事实 1 条
- 第二次任务，**无记忆**：外部判定为绿 **0/1**，平均步数 4.0
- 第二次任务，**教训+护栏**：外部判定为绿 **1/1**，平均步数 3.0，教训出现在 **3/3** 个 prompt 里
- 第二次任务，**只有已验证事实**：外部判定为绿 **1/1**，平均步数 3.0，事实出现在 **3/3** 个 prompt 里
- **一句话**：教训确实进了 prompt，但结果差异 0/1 vs 1/1，代价是**多花 -15% tokens**（1806 → 1533）。
- **成本口径（对照 vs 事实，两臂验收集合相同）**：做到验收通过要 **2.0 → 1.0 步**，**900 → 429 tokens**（-52%）。
- **正确性口径（对照 vs 教训+护栏，护栏改的就是验收集合）**：外部判定为绿 **0/1 vs 1/1**，护栏拦截 0 次。

> **「到验收通过」那两列才是工作量**：执行器要等模型「自己宣布完成」才停，
> 真实模型做完之后还会反复跑同一套测试——那是模型的确认习惯，不是工作量。
> 总步数 / 总 tokens 因此会被顶满，不该当成本口径。

> **「动了隐藏约定」是从事件流回读出来的行为**，不是自述：
> 动作事件的 observation 里出现了隐藏约定的源码，就说明模型又去打开它了。
> 这一列是「记忆到底有没有改变行为」的唯一可查证据——
> 成本没差、结果没差，但**行为也没差**，那结论就不是「记忆没用」，
> 而是「这类任务上记忆没有可测收益」。

## 四、两个记忆子系统分开算

- **教训 + 护栏**（`memory.py`）：模型读到教训 → 少走弯路；模型不听 → 护栏拦住错误写入。
- **已验证事实**（`memdb.py`）：只有事实真的进了 prompt 才有收益；「带事实的 prompt」那一列是 0/N 的话，它就是库里躺着没人看的记录。

- 护栏注入：1/1 次重复里，教训被编译成一条硬检查（`I_MEMORY_GUARD`）并加进节点的验收项。

## 五、R1 留下的那条教训

- **rep 1**｜强度 `guard`｜来源 `model`
  - 教训：Imported a symbol from another module before that module provided it
  - 原因：added the caller and the provider in separate steps without creating the provider
  - 做法：create the providing module first, then run the whole suite
  - 触发条件：files=['shop/*.py'] goals=['pricing|export|shop'] errors=[]
  - 护栏：`{'kind': 'command', 'spec': '"C:\\Users\\Charles.feng\\AppData\\Local\\Programs\\Python\\Python311\\python.exe" -m unittest discover -s tests -q', 'must': 'exit=0'}`

> 触发条件决定第二道任务**会不会真的去查这条教训**；护栏决定教训能不能变成一条硬检查。
> 两者都由模型自己写，所以「记忆存在」不等于「记忆被用上」。

## 六、这份数字不证明什么

1. **脚本模型**：数字是确定性的，方差为 0；它量的是机制，不是真实模型的表现。
2. **一个任务族**：只有「先修折扣、后改同一个文件」这一类。别的族（性能、并发、依赖升级）没测。
3. **步数不是全部**：省步数要换算成 token 与时间才是成本口径。
4. **没有对照组「模型更强」**：真正该比的不是「有记忆 vs 没记忆」，而是「有记忆 vs 换个更强的模型」。
5. **任务太容易时测不出差异**：如果模型一次就做对（先修折扣、后加参数），三条臂都会是绿的——这说明的是「**这类任务上**记忆没有可测收益」，**不是**「记忆没有收益」。要测收益，得找模型真的会犯错的场景。

## 七、决策含义

- 这一轮在真实模型上证明的是：**记忆这条路是通的**（教训进 prompt、护栏注入），
  而修之前它是**死的**。机制活不活，和机制值不值，是两件事。
- 这一轮**没有**证明记忆有价值：任务太容易时三条臂全绿，记忆只是多花 tokens。
  所以**不能说**"记忆没用"，也**不能说**"记忆有用"；只能说：
  **「记忆的价值需要一个模型真会犯错的场景才能测」**。
- `memory.py`（教训 + 护栏）与 `memdb.py`（事实）两条路径：脚本模型上收益重合，
  真实模型上**都只是成本**。合并/取舍不得在真实模型数据之前做决定，
  否则又是拿脚本模型替真实模型做决定。
