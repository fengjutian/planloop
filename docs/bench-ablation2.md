## 四个臂分别在做什么

- **B0**：单发 JSON 动作，拿不到命令输出，也没有验收。
- **B2C**：planloop 执行器（每步重新注入上下文、同一套工具、提前停止），但节点验收换成永远通过的桩 —— 模型看不到失败，也拿不到重试。
- **B2D**：同一套执行器，节点验收换成「安静判据」：失败是真的，但只回一句「验收未通过」，不带任何诊断信息。模型会被告知失败、并得到一次重试。
- **B2**：同一套执行器，节点验收是 held-out 判据，失败输出（真实 traceback）会喂回模型并触发重试。

四个臂的**最终**成功判定都是同一个 held-out 判据。唯一的差别是：

| config | 验收会不会失败 | 模型是否被告知失败 | 失败是否带诊断 |
|---|---|---|---|
| B0 | 不会（没有验收） | 否 | — |
| B2C | 不会（桩永远通过） | 否 | — |
| B2D | 会 | 是 | 否 |
| B2 | 会 | 是 | 是（真实 traceback） |

### 机制：模型到底看见了什么

只看成功率说不清 B2D 为什么是 0/5——有两种解释：

1. **安静判据让重试根本没触发**（那 B2D 测的还是 B2C）；
2. **重试触发了，但失败信息里没有诊断**，模型改不对。

这两种解释导出完全不同的结论，必须先分掉。方法是把模型实际收到的 prompt 抓下来。

**B2D 臂（真模型，`mean_empty_hidden`，16 次模型调用）**：

| prompt | 看到 traceback | 只看到"失败" | 带 supervisor 纠正 |
|---|---|---|---|
| 0-7（第一次节点执行） | 否 | 是 | 否 |
| 8-15（重试） | 否 | 是 | 是 |

**重试确实发生了**（节点执行 2 次，第二次带 supervisor 纠正），
但 16 次调用里模型一次也没看到过 `ZeroDivisionError` / `FAILED (...)`，
只看到 `exit=1 (want 0)` 和 `ACCEPTANCE FAILED: the acceptance criteria are not satisfied.`。

**B2 臂（真模型，两道题各跑一次，都是成功）**：

| 任务 | 成功 | 节点执行 | 模型调用 | 带 traceback 的 prompt |
|---|---|---|---|---|
| divide_zero_hidden | 是 | 1 | 8 | **7 / 8** |
| mean_empty_hidden | 是 | 1 | 8 | **7 / 8** |

这两行是整份报告的关键：B2 的成功**不是"模型一次就写对"**——
8 次调用里有 7 次带着真实 traceback，模型是**看着报错改对**的。
而"节点执行 = 1"说明纠错发生在**同一次节点执行内**（执行器每步都做 L1 检查，
失败输出直接进下一轮 prompt），根本没用上 scheduler 的重试。

对照起来看：

- **B2**：模型被反复告知"哪里错了"（真实 traceback）→ 改对了 → 成功；
- **B2D**：模型被反复告知"失败了"（没有诊断）→ 改不对 → 失败；
- **B2C**：模型完全不知道验收存在 → 失败。

所以 B2D 的 0/5 是第二种解释：**重试本身不是关键，失败输出里带不带诊断才是关键**。

同一套语义也由离线探针（脚本化模型，不烧 API）交叉验证，
并由 `tests/test_bench_oracle.py::FeedbackChannelTest`（3 项）守着：
B2 必须把 traceback 交给模型、B2D 必须不交、B2D 必须仍然被纠正、B2C 必须从未被纠正。

## 读法与边界

- **B2 vs B2D** 是本轮真正的新对照：两者都会失败、都会被告知、都会重试，唯一的差别是失败输出里有没有诊断信息。
- **B2D vs B2C** 隔离的是「多给一次机会」：B2D 有重试但没有信息，与没有重试的 B2C 同级。
- **B2C vs B0** 在本任务集上没有差别：执行器本身不产生收益，收益全部来自失败反馈。
- 每格样本少、只覆盖一道任务族、一个模型；p 值只说明「在这个样本上差异不是偶然」，不构成对更大任务集的普遍结论。
- held-out 判据的**路径与测试名会通过失败输出泄漏给模型**（traceback 里能看到测试函数名）。这是真实的失败反馈（相当于 TDD 的红灯），但它确实让模型知道验收长什么样；「判据不可见」只成立于「判据文件内容不可读、不可改」这一层。
- B0 那一列的「执行器调用」是**模型调用次数**（B0 没有执行器，状态一栏是 n/a）：平均 8.7 次，多数格子打满 12 步上限——没有验收闸门时模型常常不收敛，而 B2 的提前停止是它的一部分。
