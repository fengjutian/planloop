两行读数一次说清三件事：B2D 的重试确实发生了（节点执行 2 次，第二次带 supervisor 纠正）， 但模型 16 次调用里一次也没看到过真实报错；B2 的成功不是「一次就写对」——8 次调用有 7 次带着 traceback，模型是看着报错改对的； 而「节点执行 = 1」说明纠错发生在同一次节点执行内（执行器每步都做 L1 复核，失败输出直接进下一轮 prompt），根本没用上 scheduler 的重试。

负结果：这些机制对本模型不成立

诚实的负结果和正面结论一样重要：它们不能用来制造失败，只能作为「模型比预期更仔细」的记录。

成本不是常数

「验证是纯成本」是错的说法。实测三个任务族是三个数，方向甚至相反。

刻度 0 → 1.5×，│ 标记处为 1.0×（与 B0 持平）；线左 = 更省，线右 = 更贵。

模型一次就对 + 任务短 → 更省；模型一次就对 + 任务长链 → 贵 43%（每步重发整个仓库）； 模型本来就会错 → 一次失败 + 一次带诊断的重试，比盲写一遍更省。验证的价值只在该出错的场景里显现。

这份报告不证明什么

效度威胁逐条列出来，避免结论被外推。

  • 1任务集窄 —— 核心结论只来自 2 道「模型自己宣布完成」的题。roadmap 的验收门是 ≥10 个真实任务。
  • 2单模型 —— 只有 MiniMax-M3.1-Flash，是否跨模型成立未测。
  • 3样本量小 —— 每格 3~5 次；p 值只说明「在这个样本上差异不是偶然」。
  • 4判据泄漏 —— traceback 会把 held-out 测试的函数名露给模型（相当于 TDD 的红灯）。
  • 5策略会中断运行 —— 实测 1/24 的格子因模型写了嵌套 shell 触发确认规则、整轮被拦下；剔除与否会直接改变 B2D 的分母。
  • 6B2 内部未完全拆开 —— 「提前停止」与「每步复核」的贡献尚未单独隔离。

仪表自身的缺陷

本轮修掉的三个。它们都不会让程序报错，只会悄悄把结论推向有利于假设的方向——比模型出错更危险。

  • 17.1污染检查是默认值渲染出来的 —— 合并脚本里 contaminated 吃了 dataclass 默认值 False，于是「24/24 未发现副本」根本没测过。修法：从日志行的 CONTAMINATED 标记读，缺字段报错。
  • 17.2「重试次数」在真实实验里是占位符 —— 取自 getattr(model,"attempts",1)，真实模型没这个属性，恒为 1；而 B2D 的结论恰恰取决于它。修法：改从 scheduler 的 result.outcomes 取。
  • 17.3「跑了但失败」与「根本没跑完」算成同一件事 —— 被策略中断的格子被算成一次失败，等于凭空给消融假设加了一票。修法：Outcome 增加 status / blocked，按原因分类，中断的格子单列剔除。

下一阶段

按 roadmap 的验收门「≥10 个真实任务、每种配置重复运行、成功结论完全由独立 oracle 给出」，还差三件事。

  • 1补任务集（最关键） —— 把 2 道合成题扩到 ≥10 道真实任务，覆盖更多失效形态（跨模块契约、性能、并发、依赖升级…）。每道题都要有 correct / wrong 双向自检：题目本身是坏的，benchmark 会给出与事实相反的结论。修法：双向自检已做成单测，遍历所有带 held-out 判据的题。
  • 2换模型复现 —— 至少再加一个模型，检验「诊断有用」是否跨模型成立。
  • 3补上 B2 内部的剩余混淆 —— 单独拆「每步 L1 复核」与「提前停止」，并把 B0 的上下文预算对齐（早期版本 B0 只有 B2 一半）。

复现

全部命令在仓库根目录执行；API key 从 .planloop/credentials.env 自动读取（不入库）。

# 全量单测（171 项）
python -m unittest discover -s tests -t . -q

# held-out 判据对照
python -m planloop bench --real --model MiniMax-M3.1-Flash --reps 3 \
    --configs B0,B1,B2 --tasks divide_zero_hidden,mean_empty_hidden

# 四臂消融（带状态记录）
python -m planloop bench --real --model MiniMax-M3.1-Flash --reps 3 \
    --configs B0,B2C,B2D,B2 --tasks divide_zero_hidden,mean_empty_hidden

# 采样噪声轴 / 产品本体
python -m planloop bench --real --model MiniMax-M3.1-Flash --temperature 1.0 --reps 2 --configs B0
python -m planloop demo --dir .demo
